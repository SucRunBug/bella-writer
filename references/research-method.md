# 联网核实与搜索方法

第四步用。这一步无条件执行，没有「跳过」。它干两件事：一是**核实**，把第三步大纲里的关键事实、数据、结论拿去外部来源核对，确认当前正确；二是**补足**，把大纲标出的信息缺口搜齐。两件事并行做，产出喂给写作阶段。

目标不是写一份研究报告，而是把写这篇内容所需的事实、案例、数据、时间线、人物背景搜扎实、核准。信息的丰富度和准确度，直接决定成稿能不能写透。

---

## 核心原则

**必须真的联网，不能只靠记忆。** 涉及具体事实、数据、最新进展时，记忆里的信息可能过时或不准。宁可多搜，也不要因为信息不够导致内容浮在表面。

**核实和补料同等重要。** 不是只有「缺料」才联网。哪怕用户给了一手资料、主题看着纯属观点，也要把里面的关键事实拿去外部来源核一遍，确认没记错、没过时。核实不过的，回第三步改大纲。

**一手来源优于二手来源。** 多个媒体转载同一个错误，会造成「大家都这么说」的循环印证假象。能找到源头就找源头。

---

## 并行搜索

用子 Agent 并行搜，提高效率。根据选题拆分搜索方向，常见分工：

- **方向一 —— 主体信息**：选题对象本身的来龙去脉、关键事实、时间线、核心数据、相关人物背景。
- **方向二 —— 横向对照**：同类 / 竞品 / 相关方的情况，用来做对比、找差异、定位认知落差。
- **方向三（复杂选题才需要）—— 补充信息**：行业环境、用户真实讨论、争议点，来源可以是社区讨论、问答、社交平台。

给每个子 Agent 的指令里写清楚目标（「获取」「了解」「调研」），不要限定具体手段（不要写死「去搜索」「去爬」），让它自己判断最佳获取方式。

子 Agent 的联网工具使用指引（写进它的 prompt）：

> 你需要联网获取信息。
> - 用网页搜索发现信息来源、获取线索和关键词结果。
> - 拿到具体 URL 后，用网页抓取从页面定向提取内容。
> - 先搜发现来源，再抓取深入。多个关键词组合多搜几次，不要搜一次就停。
> - 一手来源优于二手：官方博客 / 公告 > 权威媒体原创报道 > 转载聚合。
> - 如果选题涉及学术概念、算法、技术范式，查 arxiv：`curl -s "https://export.arxiv.org/api/query?search_query=all:关键词&max_results=10"`，返回 XML，含标题、作者、摘要、日期、PDF 链接。找到关键论文再抓取页面细节。

## 来源优先级

| 信息类型 | 一手来源 |
|---|---|
| 产品更新 / 技术决策 | 官方博客、Release Notes、创始人公开发言 |
| 商业 / 融资数据 | 公司官方公告、工商 / 监管文件 |
| 用户口碑 | 社区讨论、问答平台、社交平台真实帖子 |
| 行业分析 | 权威媒体的原创报道（非转载） |
| 学术 / 技术原理 | arXiv、学术会议论文、Google Scholar |

---

## 怎么算核实过

对大纲里的每个关键事实，找到至少一个可靠来源支持它，才算核实过。核实结果分三种，素材池里每条都要标上状态：

- **已核实**：有可靠来源支持，且和记忆 / 用户资料一致。
- **待核实**：来源不足或有分歧。成稿里要么不写，要么明确说明「这个说法有出入」。
- **存疑 / 反例**：查到了相反的证据。这时不能硬写，回第三步改大纲。

---

## 充分性自检

搜完检查一遍：

- 主体：能不能把这件事的来龙去脉讲完整？有没有明显的信息断层？
- 横向：对照对象齐全吗？每个的信息够不够做对比？
- 核实：大纲里标记的关键事实，是不是每条都落到「已核实」了？还有没有停在「待核实 / 存疑」却没处理的？
- 来源：关键事实有没有可靠来源撑着？有没有只靠单一来源就下了判断？

不够就再补搜，别凑合。

---

## 喂给写作

搜集到的信息整理成一份素材清单，标清楚每条的来源和核实状态，交给写作阶段。注意：

- 搜不到的信息，老老实实标「暂缺」，绝不编造。写作时宁可不写，也不能造假。
- 每条都要带核实状态（已核实 / 待核实 / 存疑），写作时用哪条、能不能用，看状态。
- 把最有用的事实、案例、数据、原话挑出来，这些是写作时要落进大纲对应段落的素材。
- 整理时就和大纲对齐：哪条素材撑哪一段、对应大纲里哪个「待核实 / 待补料」标记，标清楚，写的时候不会丢、也不会漏核。
