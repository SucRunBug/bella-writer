# 个人风格档案

> 这里是**用户自己的**写作风格，是写作阶段的最高优先级参考——高于 `references/writing-style.md` 里的任何通用逻辑或候选手法。
>
> 这个文件会随每次使用慢慢长起来：第七步「风格归档」会把用户认可的、否决的写法提炼成条目，**经用户同意后**写进下面各节。
>
> 最近更新：2026-09-14

---

## 这个档案怎么长起来

每次用完 skill，第七步会回看这一轮里用户做了什么，提炼成候选条目，问用户要不要写进来。三个来源：

1. **用户对成稿的改动**：他改了哪句、换成什么词、调了哪段结构——改法本身就是偏好。
2. **用户明说的话**：像「我不喜欢这种」「以后都别这么写」「这句对了」——直接就是条目。
3. **用户的否决与跳过**：他让删掉、让别再用的手法，进「黑名单」。

用户同意的条目才写入，写入后按下面的分类归位，并更新本文件顶部的「最近更新」时间。条目要写具体，并尽量附一句用户原话或例子，方便以后判断边界。

## 一、用语习惯

- 删冗余铺垫。开头和转场里的「不是玩梗，是」「先倒回去说」这类铺垫短语，能删就删，直接上内容。——用户原话：「现在有点啰嗦了」
- 用短问句转场。「这果蝇哪来的？」这种短问句当转场，比「先倒回去说」利索得多。
- 加转折词。句子之间用「如果」「不过」「因为」「所以」「但」衔接，不要硬切。——用户原话：「还有转折词可以加上，让句子之间衔接更顺畅」
- 专业术语不翻译。「Agent」不写成「代理」。——用户原话：「13 个代理原文应该是 13 个 Agent，没必要翻译」

## 二、已确认偏好

- **价值锚优先于调性（最高优先级）。** 整活 / 段子只是钩子，不是全部。动笔前先想清楚「观众看完带走什么」（一个认知点 / 判断 / 可执行的方法），这个价值点任何时候都不能被调性、简洁化冲掉。好玩但没获得感 = 废稿。——用户原话：「感觉这篇文案没有价值点，观众看完之后没有获得感」
- **开头直接进主题，不绕弯子。** 不解释概念、不自证、不讲读者不关心的背景，第一段就可以是核心内容，多站在用户角度想读者关心什么。——用户原话：「开头直接不绕弯子」「你讲 star 数这些废话干嘛，别人根本不关心」
- **信息密度优先，不啰嗦。** 狠狠砍废话，只留硬信息，不注水。——用户原话：「写得莫名其妙和啰嗦，信息密度不高，给我狠狠整改」
- 不加入主观描述和个人观点。「我记住它是因为…」「我点进去一看」「我比较愿意推荐」这类主观发挥删掉，直接说事实和判断。——用户原话：「不要给我加这种莫名其妙的个人观点」
- 最离谱的画面放开头当钩子。科技热点选题，开头直接砸最离谱的应用场景（如「果蝇打 DOOM」），再倒回去解释来龙去脉。
- 整活 / 吐槽优先于严肃科普。同类科技热点，重心放网友整活和吐槽，不端着讲科学。
- 盘点类文章直接上货。不解释概念、按客观硬指标（如 star 数）排序、给判断，不平铺罗列。——用户原话：「一个热门 skill 一个段落，不要去解释 skill 是什么了」
- 用「它适合……的人」，不用「谁该装」这类提问式。——用户原话：「谁该装改成它适合……的人」

## 三、黑名单

- 对仗式升华金句。像「科学家想研究的是意识，网友只想知道它能不能通关」这种对仗收尾，觉得尴尬，别用。
- 铺垫式口头禅。「说真的」「说句实在话」「我特想知道」这类自述铺垫，去掉，直接说想问的、想表达的。
- 废话引导语。「先说清楚为什么现在值得关心这事」「它的自我定位一句话就能说清」「这个星数配这个覆盖面」这类空话开场白，直接删。
- 偏离主线的凑字段落。结尾的「怎么选」「避坑清单」「共同局限」这类和主线无关的，全删，主线好好写有价值的东西。——用户原话：「这里都是废话，全部偏离主线了，纯粹是凑字数」
- 网络用语解释。「从夯到拉」是网络用语，不需要解释。
