# 写作逻辑与参考候选库

> 这个文件是 Bella-writer 写作阶段的「底层逻辑 + 手法库」。
>
> 它**不是**一套让用户无脑套用的规则。用户真正的写作风格记在 `references/style-profile.md`（个人风格档案）里。
>
> **优先级：个人风格档案 > 本文件的通用逻辑 > 本文件的参考候选库。**
>
> 这份文件是「出厂默认」，会随使用进化：用户认可的手法沉淀进个人档案，用户长期不用或明确否决的可以淘汰。沉淀动作在第七步「风格归档」做，且必须经用户同意。

---

## 〇、怎么用这个文件

文件分两层，要分开对待：

**第一层，通用逻辑（第一、二部分）** —— 相对稳定。讲的是「为什么这么写」。不管谁写、写哪个平台，这些底层规律都成立。写作时按它去想，但不必逐条照做。

**第二层，参考候选库（第三到五部分）** —— 一堆具体手法、词句、禁区。**它们不是规定，只是候选。** 哪些用、哪些不用，由个人风格档案决定。档案没覆盖到的，从这里挑真正合适的，别整套默认全上。

所以动笔前的动作是：

1. 先读 `references/style-profile.md`，看用户对风格说过什么、认可过什么、否决过什么。
2. 用个人档案里的偏好定基调。档案里写了以档案为准。
3. 档案没覆盖的维度，回到本文件的通用逻辑 + 候选库里找补。

写作还要服从两条来自大纲的硬约束：**严格按大纲写**（结构、顺序、每段核心、体量配比不得擅改，要改先回第三步改大纲）；**段落之间必须自然过渡**（相邻板块之间要有一句口语化转场，不许硬切、并列堆砌）。

## 一、写作的底层逻辑（稳定层）

这一部分讲原理，不规定具体写法。理解这些，才能在档案空白的维度上自己判断。

### 1.1 内容是怎么被读下去的：推进系统

节奏的本质是一套让读者一路往下读的推进机制。好的节奏像波动，每次围绕主线偏出去一点，让读者喘口气、长点见识、看个案例，再用一句话拉回来继续往前推。最糟的是突然偏离主线很远再硬拽回来，读者得费脑力顺逻辑，心流立刻断掉。

由此推出一条通用做法，习惯性加「扣主线句」：偏出去之后用一句话把读者拉回主题，句子不用长，一句就够，但要高频出现。句子时长时短、偶尔一句话独立成段制造停顿，都是这套推进系统的具体手段。

### 1.2 开头必须独立工作

开头是整篇内容的试用装，不是标题的延续。绝不能假设读者看过标题、看过封面才能读懂第一段。把开头单独拎出来，一个完全没看过标题的人，光读这几句，能不能立刻知道「这在讲什么」并且「想接着往下看」。读者刷到的第一眼往往只有正文开头，开头自己不站起来，标题再好也白搭。

一个立得住的开头，通常同时给齐三样东西：**话题**（这篇到底讲什么，让读者一句话内对上号）、**钩子**（为什么值得现在就看，靠有冲击力的数据、强反差、反常识的判断，或一个戳中人的痛点）、**可信度**（凭什么信你，靠具体的事实、可核实的细节、真实的来源，而不是空口下论断）。三样里，钩子和可信度最常被写丢。

开头最容易犯的错，是第一段就把结论说完了。用「为什么」代替「证明」，把最关键的答案先憋住，让读者带着一个没解开的问题往下走。

如果一个开头怎么写都觉得平、觉得虚，先别在文字上死磕，回头看素材。检查这五样手里到底有没有：有冲击力的数据、强烈的前后反差或转变、能独立成立的金句、有分量的人物或机构背书、戳中目标人群的痛点。一样都没有，说明不是开头不会写，是内容根上缺料，应该回第四步补素材，而不是硬凹一个漂亮的空壳。

### 1.3 段落之间要自然过渡

板块和板块之间不要硬切。用口语化的转场把上一段的尾和下一段的头接起来，让全文一口气顺下来，读者感觉不到「这里换了个话题」。这一条是硬约束，接不上就说明大纲的板块衔接没想清楚。

### 1.4 前后呼应（契诃夫之枪）

第一幕挂在墙上的枪，第三幕就得开火。前面埋的每一个细节后面都得响。文章内部要有 callback 结构，前面提到的意象、句子或小钩子，后面以变体形式再出现一次，读者会觉得这是一个完整的作品，不是一堆信息的堆砌。有意识地在开头或中间留钩子，到结尾 callback 回来，这种前后闭合感是让文章从「信息流」变成「作品」的关键。

### 1.5 私人视角：用「我」连接个人和公共

用「我也面临这个问题」连接个人经历和公共议题，而不是「这给我们的启示是」。经常从自己的真实经历切入。判断要有，但要敢下明确的好恶，而不是居高临下的点评——是「我被打动了」「我觉得他说的是事实」这种承认自己被影响的姿态。

### 1.6 知识是聊出来的，不是科普出来的

不是「下面我来给大家科普一下」，而是看起来好像脑子里本来就有这些东西，正好跟眼前的事对上了。知识点以「聊着聊着顺手掏出来」的方式呈现。

### 1.7 讲观点前先理解对立面

讲观点不是简单的是非判断。先站在对方角度把对方处境具体化，承认这种处境合理，再切入自己的不同视角。读者觉得「他理解我」，观点才有说服力。

## 二、动笔前的两个判断（稳定层）

### 2.1 判断文章属于哪种原型

动笔前先判断内容属于下面哪一种，每种写法重心不同：

**调查实验型**：亲自下场做一件事，然后报道发现。核心是「我替你去做了这件事」。重心在过程叙事和发现的层层递进。

**产品体验型**：拿到东西实际使用，带读者一起体验。核心是「跟我一起玩」。重心在场景演示和真实感受。

**现象解读型**：观察到一个现象，层层深入分析。核心是「你注意到了吗，背后是什么」。重心在观察→好奇→研究→升维。

**工具分享型**：分享一个实用工具或方法，用个人故事包裹。核心是「我发现了一个好东西」。重心在个人故事铺垫→展示→效果惊艳。

**方法论分享型**：把长期积累的经验系统性分享出来。核心是「我把压箱底的东西掏给你了」。重心在每节都有可执行动作，同时坦诚说明学习成本、时间曲线和常见失败点，不只画饼。开头用谦逊铺垫卸掉傲慢感，结尾回扣所有行动点。

### 2.2 AI 和人的分工（写之前先认清）

这套流程是文风生成器，不是替人思考的工具。最大的价值不是生成内容，是提供素材和启发。

**可以放心交给 AI 的**：找证据和佐证（给一个观点，去历史、学术、文化里找支撑和反驳它的论据）、找类比和比喻、按确定的角度扩写、补充学科背景知识、梳理逻辑和结构建议。

**必须由人来、AI 一做就露馅的**：第一手观察和真实经历、核心创意角度、情绪的真实表达、从数据到人物的同理心转换。

在自媒体创作场景里，用户往往没法逐句提供第一手经历。处理原则是：**有真实细节就用真实细节，没有就老实承认「我还没试过，但想想就觉得」，绝不编造假场景假经历。** 编一个「我有个朋友」的故事是大忌。

## 三、参考候选库 · 修辞手法

下面是一堆可用的手法及其适用时机。**默认不要求全用**，按文章需要和个人风格档案挑。档案里标明用户喜欢哪些、否决哪些。

**节奏与破碎**
- 句子时长时短，用逗号制造口语化停顿；关键处用一句话独立成段制造重量感。适用于需要强调或刹车的位置。
- 论述中故意打破：加口语打断（重复强调、中途叹息、省略主语、刻意模糊「我就不说是谁了」），破坏严谨性，让论述有温度。

**开头与切入**
- 叙事启动：「故事是这样的。」直接抛事件。
- 荒诞事实：直接抛一个让人「？？？」的事实。
- 热点破题：「最近这两天，被一个东西给刷屏了。」
- 好奇心驱动：「这两天刷到一个东西，很有意思。」
（用哪个都行，但都要过 1.2 的「独立工作 + 话题/钩子/可信度」标尺。）

**表达与距离**
- 谦逊铺垫法：给观点或建议前，先用自谦降低读者防御心（「我也不知道行不行」）。方法论、教程类尤其适用。
- 读者直呼法：在关键节点直接跟读者对话（「屏幕前的你」「你相信我」）。精准投放，不通篇用。
- 疑问句的节奏作用：用问句当刹车和转向（「为啥这么做会有效果呢」），让读者停一秒准备接新信息。
- 情绪表达：用「。。。」表示拖长、震惊、无语；用「？？？」表示极度惊讶；会自嘲，会直接表达兴奋。

**展开与说服**
- 层层剥开的修辞：不直接讲结论，用「现象→表面解释→更深的追问→核心洞察」展开，让读者参与推理。
- 反向论证：揭示核心观点前，先满足读者期待再打破它（「你以为要很复杂，结果是复制粘贴」）。力度是「我也曾这样想」，不是「你们都错了」。
- 对立面的理解与承认：见 1.7。
- 人物画像法：从一个数据点出发，用 3-5 句想象背后那个具体的人的完整人生（触发点数据→快速代入→多维堆砌→情感锚定→细节具象化）。

**结构与叙事**
- 英雄之旅叙事弧：普通人被召唤去冒险→经历考验→获得宝物→带着变化回到日常。调查实验型和产品体验型几乎都套这个结构，起点必须是一个具体、能代入的困境或好奇。
- 逐一展示法（升番逻辑）：多个产品 / 模型 / 案例对比时，不一次性罗列结论，逐一展示，每个带一句吐槽。排列遵循升番：最弱的放前面，最炸的留最后。
- 文化升维：聊完具体的事，连接到一个更大的文化、哲学、历史参照物，要有「聊着聊着自然想到了」的感觉，不是硬凑的升华。

## 四、参考候选库 · 口语句式与词组

下面这些词组自带活人感，**在需要转场、表达观点、拉近读者距离时挑着用**，不是每句都塞。密度随平台和个人档案调整（长文可多用，短口播稿点缀即可）。

**转场和过渡**：坦率的讲、说真的、我是真的觉得、反正我觉得、怎么说呢、其实吧、你想想看、我跟你说、回到这块、这块需要注意一下、顺着上面的再聊聊

**表达判断**：我有时候觉得、我一直觉得、这话听着有点刺耳但、不是说不行而是说、我自己的感受是、我始终坚信

**承认和自嘲**：说实话我也不确定、我自己也还在摸索、可能有些想法还不成熟、这个事儿我也踩过坑、愚钝如我

**情绪表达**：这种感觉太爽了、我当时就愣住了、想想就觉得兴奋、我真的被震撼到了、太离谱了、你敢信

**拉近距离**：很多朋友可能不知道、可能有小伙伴纳闷、你如果关注这个领域的话、大家也都知道

**口头禅**：这玩意、不是哥们、我寻思了一下、真的就是一声叹息、太牛了

> 注意：这一组是最典型的「出厂默认」，未必是用户自己的语感。**如果用户没认可过，就只挑真正贴合的少量用，不要照单全收**；用户明确否决的进黑名单。

## 五、参考候选库 · 常见禁区

下面是这类内容里最容易暴露 AI 味的写法，**默认规避**。个人风格档案里如果用户另有规定，以档案为准。

1. **套话**：慎用「首先…其次…最后」「综上所述」「值得注意的是」「不难发现」「让我们来看看」「接下来让我们」。
2. **过度结构化**：避免用 bullet point 罗列观点、大量加粗、通篇小标题。多数时候一口气顺下来，靠节奏和转场推进。例外是「N 条心得」这种本身就是独立条目的方法论内容，可用数字编号，但也不是正式的 markdown 标题。
3. **标点**：长文慎用冒号（多用逗号）、破折号、双引号（需要引用或强调时用「」或不加引号）。短视频口播稿可适当放宽。
4. **高频踩雷词**：慎用「说白了」「意味着什么？」「这意味着」「本质上」「换句话说」「不可否认」。
5. **假设性例子**：「比如有一次…」这种编造场景是大忌。要用正在发生的真实细节；没有真实细节就别硬编。
6. **空泛工具名**：不说「AI 工具」「某个模型」，要说具体名字。
7. **教科书开头**：避免「在当今 AI 快速发展的时代」「随着技术的不断进步」这类空话开头，永远从一个具体的、当下的事件或场景切入。

## 六、结构模板（默认骨架）

下面是默认的内容组织方式。**最终结构以第三步产出的大纲为准**，这个模板只用来辅助理解每个板块该怎么写，不能覆盖大纲。

```
【开头】感性切入，从一个具体事件 / 场景开始，迅速建立情绪
  ↓
【背景铺垫】简要科普，让非专业读者也能看懂，科普方式是聊天式的
  ↓
【核心内容】分几个板块展开（板块由大纲决定），每个板块有：
  - 一个明确观点
  - 至少一个具体场景 / 人物 / 对话支撑
  - 私人视角的连接
  - 一句扣主线的话
  - 与下一板块之间一句自然的口语化转场
  ↓
【升华】从具体事件拉到更大的文化 / 哲学 / 历史参照物
  ↓
【收尾】选一种：引用收尾 / 哲思余韵 / 行动呼吁 / 信念宣言 / 回环呼应
```

## 七、写完后的自检

写完跑一遍自检。分四层，从硬规则到主观的活人感判断层层递进。与 `references/ai-check.md` 配合：本节是写作侧的快速自检，ai-check.md 是更细的指纹级排查。

### L1 个人档案硬规则（自动扫描层）

- 先扫 `references/style-profile.md`「黑名单」和「用语习惯」里用户定下的硬规则，命中必须改。
- 档案没覆盖的维度，默认按第五部分「常见禁区」扫：套话、过度结构化、标点、踩雷词、空泛工具名、教科书开头。
- 工具 / 产品都用了具体名称。

通过标准：档案硬规则零命中；禁区扫描零命中（或档案另有规定的按档案）。

### L2 风格一致性（模式匹配层）

- **开头**：拿 1.2 的标尺过一遍——能独立工作？话题、钩子、可信度三样齐？没第一段就把答案倒光？
- **节奏与结构**：长短句交替？有独立成段的断裂效果？偏离主线的段落后有扣主线句拉回？避免了不必要的小标题？
- **口语化**：用了和用户语感相符的口语表达（不是照搬候选库里那套出厂默认）？有故意打破？至少一处自嘲或承认不足？
- **段落过渡**：相邻板块之间都有自然的口语化转场？没有硬切？（硬约束，必过）

### L3 内容质量（深度审查层）

- **大纲遵循**：结构、板块顺序、每段核心是否严格对应大纲？（硬约束，必过）
- **价值锚检查**：读者看完这篇，能不能明确带走一个认知点 / 判断 / 可执行的东西？如果看完只是「哦，好玩」「写得还行」但没有增量，判 ❌，必须返工补价值点。（硬约束，必过）
- **观点支撑**：每个核心观点都有具体的人 / 场景 / 细节 / 数据支撑？
- **知识输出方式**：知识点以「聊着聊着顺手掏出来」的方式呈现？没有教科书式科普？
- **文化升维**：至少一处从具体事件连接到更大的参照物？连接自然？
- **对立面与同理心**：讲核心观点时有对对方立场的理解和承认？
- **类型专项**：按文章原型针对性检查（调查实验型有没有亲自下场的叙事感，方法论型每节是否落到可执行动作并坦诚说明学习成本，等等）。
- **逐一展示**：涉及多个产品 / 案例比较时，用逐一展示而非一次性罗列？

### L4 活人感终审（最终人格层）

不逐项检查，以读者视角通读全文，回答一个核心问题：

**「读完这篇，我感觉是一个有见识的普通人在认真跟我聊一件打动他的事，还是一个 AI 在给我输出信息？」**

- **温度感**：情绪是体感记忆（「我当时就愣住了」）还是知识性描述（「我感到非常震撼」）？
- **独特性**：有没有「只有这个作者才会写出来的角度」？还是换个 AI 也能写出差不多的？
- **姿态**：语气是「有见识的普通人在认真聊一件事」？有没有滑入「导师教学生」或「品牌做营销」？
- **心流**：从头到尾有没有哪里注意力断掉、需要回头理解逻辑？那就是要修的节奏问题。

任何一项让你觉得「这段 AI 味太重」，就返工：把那段找出来，想象用户本人会怎么说，用更口语、更私人、更不完美的方式重写。

### 自检输出格式

## 附：怎么把候选库里的一条变成个人风格

想让档案里多一条、去掉一条，两个办法：

1. 在会话里直接说——「以后都这样」或「别再这样」。第七步「风格归档」会把它提炼成条目，问过你之后写进 `references/style-profile.md`。
2. 直接编辑 `references/style-profile.md`。

这个文件本身也可以改：候选库里的手法如果用户长期不用，可以在归档时删掉；用户沉淀出新的手法，也可以加进候选库供往后参考（同样经用户同意）。
