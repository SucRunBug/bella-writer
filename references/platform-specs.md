# 平台成稿规则

写作阶段的字数和成稿形态由目标平台 + 第一步定的体量共同决定。不管哪个平台，内容结构都严格按第三步的大纲走，写作风格以 style-profile.md 为准（见 writing-style.md），平台主要改变最终成稿的篇幅和形态。

下面每个平台给的区间是**默认值**。用户在第一步指定了字数或口播时长的话，以用户指定的为准，这里的区间只作参照；用户没指定，就按默认区间走。

第一步问体量时给的「短 / 中 / 长」三档，就是把各平台区间的下段 / 中段 / 上段；用户直接给具体数字的，用用户的。

---

## 各平台规则

### 公众号

- 形态：长文
- 字数：4000 - 8000 字
- 特点：一口气顺下来，不加小标题，靠节奏和口语化转场衔接。这是长文写作内核最原生的形态。
- 段落短，重要观点前后留白。需要配图的位置标注「图片」。

### B 站

- 形态：中长视频口播稿
- 字数：1000 - 3000 字
- 特点：口语化、能被念出来。要有清晰的起承转合，适合 5-15 分钟的视频。
- 写成可以直接对着镜头念的稿子，不是书面文章。

### 抖音

- 形态：短口播稿
- 字数：200 - 400 字（约 60-90 秒）
- 特点：开头三秒必须抓人，节奏快，一个核心点讲透就够，不贪多。
- 每句话都要能念、能听懂，去掉一切书面腔。

### 视频号

- 形态：短口播稿
- 字数：300 - 500 字
- 特点：比抖音略长、略稳。受众偏成熟，可以稍微多一点铺垫和情绪。
- 同样是口播稿形态，能直接念出来。

### 小红书

- 形态：图文大字报 或 短口播
- 字数：300 - 800 字
- 特点：标题和首图最关键。正文适合分点、适合保存。如果是教程 / 清单类，做成可保存的大字报；如果是观点 / 故事类，可做成短口播。
- 多用换行和留白，方便手机阅读。

### 全平台

- 形态：以公众号长文为母版，再裁出各平台版本
- 做法：先按公众号长文写一篇完整的母版（4000-8000 字），把事情讲全讲透。然后基于同一份大纲和母版，裁切出各平台的版本：
  - B 站：从母版抽主干，改成口播稿
  - 抖音 / 视频号：抽最炸的那个核心点，做成短口播
  - 小红书：把核心结论和步骤提炼成图文大字报
- 所有版本共用大纲的内容结构和同一套写作内核，只是篇幅和形态不同。核心观点和价值锚在所有版本里保持一致。

## 通用原则

- 字数区间是参照，不是硬指标。用户没指定体量时按默认区间走，指定了以用户为准；宁可为了讲透多写一点，也不要为了凑字数注水。
- 报字数必须实际数过，不许凭感觉估。给用户或质检报告里写字数时，要么用工具真数（如 `python3 -c` 数字符、`wc -m`），要么不写具体数字。绝不写「约 X 字」这种没数过的估值，这等于在质检报告里自己造了一个无源数字，违反成稿事实核查的底线。中文字数以汉字字符数为准，不含空格和标点时要说明口径。
- 形态决定语态：长文是「写」出来的，口播稿是「说」出来的，写口播稿时要默念一遍，念不顺就改。
- 不管什么平台，开头都要从一个具体的场景或事件切入，不许宏大叙事开场。
